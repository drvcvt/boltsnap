# README und Doku: kurz und anschaulich (Plan, 02.11.)

Nutzer: „die README ist btw auch viel zu lange, hat noch zu viele
codingartefakte […] generell muss alles anschaulicher im repo werden“, dazu
„professionell, kein AI Bullshit […] beispiele zeigen wie bisher“.

## Befund

- `README.md` 746 Zeilen. Davon richten sich an Nutzer nur Einstieg, Bilder,
  Benchmark, Installation, Befehle und Tastenbelegung; der Rest ist
  Referenz (alle Konfig-Schlüssel, Socket-Rahmenformat, Speicherregeln beim
  Aufnehmen, Matroska-Zeitstempel, Plugin-Bau) und Mitwirken (Plattformgrenze,
  Agentenregeln).
- Interna mitten im Text: Commit-Hashes, „predate the libway replacement“,
  Verweise auf Review-Befunde, Banner für AI-Agenten als erste Zeile.
- Bilder: drei headless gerenderte Screenshots (Settings Shelf, Settings
  Recording, Aufnahme-Steuerung); der Benchmark nur als Tabelle.

## Ziel

- README unter ~200 Zeilen, für jemanden, der Boltsnap zum ersten Mal sieht:
  was es ist, wie es aussieht, wie schnell es ist, wie man es installiert und
  bedient. Jede Funktion mit ein paar Sätzen und einem Link in die Anleitung.
- Referenz in `docs/guide/`, Mitwirken in `.github/CONTRIBUTING.md` (GitHub
  zeigt es an), beides inhaltlich unverändert übernommen, nur Interna
  gestrichen oder in die Codebase-Doku verschoben.
- Benchmark zusätzlich als Balkendiagramm (SVG, hell und dunkel lesbar), aus
  einem Skript erzeugt, damit es mit der nächsten Messung neu entsteht.

## Aufbau

README:
1. Titel, ein Absatz was es ist, ein Satz zur Geschwindigkeit.
2. Bilder (die drei bisherigen).
3. Funktionen (kurze Liste in Nutzersprache).
4. Benchmark: Diagramm, kleine Tabelle (Tool, Median, Faktor), Satz wie es so
   schnell ist, Link zur Messdatei.
5. Installation: Release (deb, Tarball), aus Quellen (Arch, Debian), Nix;
   Details und Windows in `docs/guide/install.md`.
6. Benutzung: Befehle, Tastenbelegung, Pipe in einen Editor.
7. Shelf, Aufnahme, Replay, Einstellungen: je 3 bis 6 Zeilen und Link.
8. Plattformen: kleine Tabelle, Protokolle in der Installationsanleitung.
9. Mitwirken (ein Satz, Link), Lizenz.

`docs/guide/` (neu, 5 Dateien; Abweichung: `screenshots.md` für Befehle,
Selector und Editoren kam beim Aufteilen dazu, sonst hätte es keinen Ort):
`install.md` (alle Wege, Abhängigkeiten,
Launcher-Eintrag, NixOS-Hinweise, Windows, Wayland-Kompatibilität),
`shelf.md` (Bedienung, Daemon, Socket für andere Programme),
`recording.md` (Aufnahme, Steuerung, Speicherregeln, Smooth Cursor,
Skript-Befehle, Konfig-Schlüssel), `configuration.md` (`config.toml`,
`[shelf]`, Einstellungsfenster).

`.github/CONTRIBUTING.md`: Agenten-Hinweis, Bauen und Testen, Plattformgrenze,
Verweise auf Codebase-Doku und Performance-Berichte. `AGENTS.md` und
`PORTING_PLAN.md` zeigen dorthin statt auf `README.md#contributing`.

`tools/benchmark_chart.py` schreibt `assets/benchmark.svg` aus den Zahlen der
Messdatei (Median je Tool, logarithmisch wäre unehrlich: lineare Achse).
